# 第 3 段：离线下载

对应提示词 `docs/prompts/07-manga-opt-3-stages.md` 第 3 段，以及 `06-manga-3-stages.md`
第 3 段的设计。这里记的是实做结果：落在哪、索引长什么样、哪些地方跟原设计不一样、
哪些没在真机上验过。

提交：`ff0fdee manga/s3: 离线下载（落盘索引、.part 续传、空间预检、进度、批量入口）`

---

## 落盘

```
<应用目录>/manga/<站点安全名>/<书目录>/<话目录>/001.jpg 002.jpg …
<应用目录>/manga/<站点安全名>/index.json
```

- 站点名过一遍白名单（非 `A-Za-z0-9._-` 换成 `_`），免得 URL 里的 `/` 跑进路径。
  用站点 key 而不是域名：换域名不换目录。
- `index.json` 先写 `index.json.tmp` 再 rename，写一半被杀不会留半截 JSON。
- 索引读不出来（真坏了）改名 `index.json.bad` 留现场，当没下过处理。
  代价是书架上的「离线」标记会消失，重新下一话就又有一条完整索引——不崩、不卡住。
- 索引**只存文件名**（`001.jpg`），不存带域名的绝对地址。站点换域名时，
  存了绝对地址的索引整批作废；存文件名，换个站还是这批文件。

## 索引格式

```json
{
  "books": {
    "<书目录>": {
      "title": "…", "cover": "…", "total": 123, "at": 1700000000,
      "bytes": 12345678,
      "chs": {
        "<话目录>": { "pages": 18, "bytes": 5500000, "at": 1700000000,
                      "files": ["001.jpg", "002.jpg"] }
      }
    }
  }
}
```

「整本离线」的判断靠 `total`（下的时候从详情页记下来的总话数）比 `chs` 的条数。

## 两种粒度

- **单话**：详情页章节格子长按进多选，勾几话一起下。
- **整本未读**：`downloadUnread`，只排还没下过的话。两万本的书一口气全排会把队列
  撑爆、也让「取消」变成按不完的键，所以按话入队、可以中途取消整个 job。

只下书架上那些**内部书源**的书。书源的图是源站现取的、地址有时效，存下来过几天
就是一堆打不开的文件，白占地方；阅读器里 `loader` 有值就不查离线索引。

队列并发 2（`_maxWorkers`），一话内部逐页串行。取消走 `CancelToken`：
排队里的任务直接剔掉，正在跑的那一页下完就停。

## 续传

每页先落 `<name>.part`，中断/失败就留着。下次从已有字节往后要，走 `Range`：

- 服务器回 206：接在后面写。
- 回 200（不支持 Range）：整段重写，别把两段字节拼成一张坏图。
- 收尾 `part.rename(final)`——只有 rename 成功才算这一页下好了，
  所以索引里的文件一定完整。

`.part` 留在原地这件事有个好处：杀进程、断网、切后台冻住，重进接着来。

## 本地优先取页

阅读器 `_load` 会把这一话已下到的页做成「网络地址 → 本机路径」的映射，
`_img` 先查它，命中就 `mangaFileImage` 读文件。文件坏了（下了一半断了、
被系统清掉）回落网络，不让读者对着一块空白。web 端没有这条通道，直接走网络。

## 空间预检

开下之前算一遍：`页数 × 300 KB`（源里的图压得狠，实测均值），话没有页数时
按每话 18 页估。剩余空间用 `df -k <应用目录>` 问，问不到（返回 -1）就不拦。

不够就**直接拒绝**，并把话说清楚：

```
空间不够：预计要 8.4 MB，只剩 3.1 MB
```

不做「下到一半再报错」。

## 进度看得见

三处：

- 书架卡片左下角小标：离线到第几话 / 正在下的百分比。
- 详情页章节格子上的勾与进度条：`MangaDown` 是 `ChangeNotifier`，索引或进度一变就重画。
- 下载中心（`widgets/manga_dl_section.dart`）：每本的进度、失败数、剩余字节，
  长按删离线文件（带确认）。

进度优先按页算（`pagesDone / pagesTotal`），页数还未知时退回按话算，
这样开下那一下不会停在 0%。

## 测试

`test/manga_download_test.dart`（这一轮重新跑过，全过）：

- 索引解析：字段齐全 / 缺字段不抛 / 空 body 不抛
- 路径拼接：`001.jpg` 能拼出正确路径，越界返回 null
- 估算字节：未知页数按 18 页/话

`flutter analyze lib`：零问题。`flutter test`：156 条全过。

## 没验的

- **真机断点续传**：`Range` 接续、200 回落这两条只有单测和代码路径覆盖，
  没在手机上真杀过进程验（这台机器上没装模拟器）。
- **iOS**：`df` 在 iOS 上未必有，`mangaDlFreeBytes` 会拿到 -1 → 不做空间预检，
  下载照样能跑，只是不拦。iOS 客户端本来也没出过包。
- **2 万本书的「整本下载」**：没真跑过，只验了 20 话以内的队列与取消。

按提示词的要求，这三条写在这儿，不算过。
