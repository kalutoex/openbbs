## P2

### 1. 写操作超时会跨入口重发 —— 发帖变两条（已复现，已修）

`Api._withFailover` 是入口回落：当前出口连不上就换 v4/v6 另一条重来。问题是它对
**所有方法**一视同仁，包括 `POST`。

线上两条入口指向同一个后端，所以真实场景是：

```
v6 入口发出 POST /threads，服务端已写库 → 回程慢，客户端 15 秒超时
→ 换 v4 入口再 POST 一次 → 第二条帖子
```

上传同理，一份文件存两份，还多占额度。

**实测**（两条本地假入口，第一条延迟 40 秒响应）：

| | 修复前 | 修复后 |
|---|---|---|
| 慢入口收到 | 1 次 | 1 次 |
| 快入口收到 | **1 次** | 0 次 |
| 客户端结果 | 静默成功 | 报连接失败 |

**改法**：`_withFailover` 加 `retryOnTimeout` 参数，默认 `true` 只给 `GET`；`post` / `patch` / `delete` / `uploadImage` / `uploadFile` 全部传 `false`。
超时直接报错，让人自己重试——宁可他重按一次，也别悄悄发两条。
`postAt`（登录/注册/找回密码）同样处理：它有自己的入口循环，超时也停。

**代价**：写操作在「v6 慢、v4 通」时不再自动跨入口，会看到一次失败提示。
换取的是不重复写。以后真要做好，得走幂等键（见下）。

### 2. 令牌被服务端废掉，客户端装作还登录着（已修）

只在冷启动 `refreshUser` 时认 401。用着用着令牌失效（管理员重置密码、服务端换密钥），
之后每一次点赞、发帖、私信都回 401「请先登录」，页面把它当普通错误弹 toast，
用户被卡在原地，也没有任何入口回到登录页。

**改法**：

- `Api.onUnauthorized` 回调，`_decode` 里命中「401 + 带令牌 + detail 是『请先登录』」时触发。
  文案判据和封禁那套一致（都是服务端写死的）。
- `AppState._tokenExpired`：清令牌、清 user、缓存作用域退回 guest、删落盘令牌、通知界面。
- 不自动弹登录页——未登录浏览是允许的，弹窗会打断。下次要身份的操作会自己引到登录页。

只认「请先登录」这一句，登录页密码输错（「用户名或密码不对」）不会误踢。

## 已验证通过

- 断网回落：`GET` 命中磁盘缓存 `cache: true`（只有 feed 用），界面标「离线」
- 缓存按账号隔离：`httpcache/guest` 与 `httpcache/u3` 分目录，切号连内存图缓存一起清
- 令牌双写：Android Keystore + prefs，Keystore 读失败退回 prefs，不会莫名掉登录
- 下载断点续传：`Range: bytes=N-`，服务端回 200 时自动从头覆盖写
- 上传 30 分钟超时，不是默认的几十秒
- 文件浏览器权限：Android 11+ 要「所有文件访问」，10 及以下退回普通存储权限；
  从系统设置页回前台会自动重查一次
- 封禁：403 + 固定文案 → 整棵树换成封禁页
- 站点探路：v6 3 秒 / 其余 10 秒，串行（保证稳定落在 v6），站点页并发只做报告
- `Api.configured` 未配置时所有请求直接报「请先配置站点」，不会打空地址
