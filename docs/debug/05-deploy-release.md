## P1

### 1. /go 兜底入口页指向 10-21 就下线的地址（已修）

`web/go.html` 里两处链接和一段探测脚本都写死老域名：

```
直连  https://bbs.kalutoex.dpdns.org:8443/     ← 10-21 随 Host: bbs 分支一起停用
备用  https://bbs.kalutoex.dpdns.org:36776/    ← 同上
js 探测 u = 同一地址 → fetch version.json 必然失败
```

也就是说：这个页面的用途是「给没有 IPv6 的人一个入口」，而它给的两个入口都已失效，探测还会恒定提示「连不上直连入口，用备用那个」，然后备用也是死的。整页等于没用。

**改法**：链接换成现在的正式入口，探测地址一并对齐。

```
直连  https://ipv6bbs.kalutoex.dpdns.org:26016/
备用  https://ipv4bbs.kalutoex.dpdns.org:24016/
```

静态文件即时生效，已复验：`/go` 200、页面里两处 ipv6bbs、`version.json` 200（探测目标存在）。

顺手记一笔：`go.html` 只活在线上 `server/web/`，`openbbs/web/` 和构建产物里都没有。`deploy_web.sh` 只做 `cp -r` 覆盖，不会删它，所以眼下安全；但**换机器重新部署会丢**，建议收进仓库（见建议 4）。

### 2. 保活脚本 pid 文件与真实进程脱节，cron 每两分钟空起四个（已修）

现象：`data/forum4.pid` 等四个文件每两分钟被刷新一次，指向的进程一个都不在；`forum.log` 里 `address already in use` 已经积了 74 条。

原因链：

1. 20:19 那次重启留下的 4 个进程不是 run.sh 起的（旧命名 `data/forum.pid` 只记了其中一个），所以 run.sh 的四个 pid 文件里没有它们；
2. run.sh 只信 pid 文件：读到的 pid 是死的 → 起新进程 → 端口被真实进程占着 → bind 失败退出；
3. 但它退出前已经把自己的 pid 写进了 pid 文件。下一轮读到这个 pid，又是死的，再起一个。循环成立。

后果有两层。表层是每两分钟 4 个进程白起、日志刷错误。深层更麻烦：**pid 文件不可信**，按 pid 做运维（停站、看负载、查进程）会全部落空，`run.sh --stop` 也停不掉真正在跑的服务。

**改法**：`up()` / `up_tls()` 在起进程前先 `adopt`——扫 `/proc`，找 cmdline 里同时含 `uvicorn`、`app.main:app`、`--host <host> --port <port>` 的进程，找到就把它的 pid 写进 pid 文件并返回，不再重复启动。找不到才真起一个。

验证：

| 检查 | 结果 |
|---|---|
| 手动跑一轮 run.sh | 4 个 pid 文件全部指向真实进程（1735527 / 1735529 / 1743634 / 1735530） |
| 跨两轮 cron | `address already in use` 计数停在 74，零新增 |
| 自愈 | 20:44:31 杀掉 [::]:8080，20:46:00 被 cron 拉起（1756726），pid 文件同步，接口 200 |
| 另三个端口 | 全程未受影响 |

恢复时间约 90 秒（cron 周期 `*/2`），与设计一致。

### 4. 8080 明文端口对公网开着

`ss` 显示 `0.0.0.0:8080` 与 `[::]:8080` 都在监听，INPUT 策略 ACCEPT，没有任何 v6 白名单。外部扫描器用 IPv6 直连就能打到明文站：登录接口、老页面、整套 API 都在。

历史设计是「share 域名指到 8080」，share 11-02 已删，但端口没跟着收。现在它的唯一作用大概是局域网调试。建议二选一：绑局域网地址，或者加一条 v6 来源白名单。这属于网络配置，按约束没动。

**2026-11-05 处理**：`bbs/release.sh` 已删除（提交见 bbs 仓库），只留 `openbbs/release.sh`；8080 改成绑局域网地址 + `::1`，`run.sh` 每两分钟按当前地址校正（DHCP 换地址会自动换绑），公网 v6 实测连不上，26016 不受影响。

1. 删 `bbs/release.sh`——只留 `openbbs/release.sh`，消除「用错脚本」的可能。
2. 8080 绑 `127.0.0.1` + 局域网段，或加 v6 白名单；26016/24016 保持不变。

## 交接说明

1. **发版认 `openbbs/release.sh`**。`bbs/` 里那份是旧的，别用。
2. **pid 文件现在是准的**。停站用 `bash run.sh --stop`，或按 `data/forum*.pid` 里的 pid 杀。别再用 `pkill -f uvicorn`——第 1 段已经踩过一次，会把执行命令的 shell 一起带走。
3. 手工起的进程 run.sh 会自动接管（`adopt`），但这只保证不再刷错误，进程归属仍然乱。**要重启就整个 `--stop` 再 `run.sh`**，别只补一个。
4. `/go`、`BOT_API.md` 是两处最容易和现实脱节的静态/文档，改端口、换域名时一起改。
5. 本段改动：`server/run.sh`（adopt）、`server/web/go.html`（入口地址），都在 bbs 仓库。
